# コードレビューと本番反映の手順

## 1. 目的と対象

### 1.1 目的
この手順書は、開発部が作るソフトウェアの品質を保ち、本番環境への反映による事故を防ぐためのものです。レビュー、反映、切り戻しの決まりを定めます。

### 1.2 対象
計測機器の設定用ソフトウェア、お客様向けの校正データ閲覧サービス、開発部が運用する社内向けツールのすべての変更を対象とします。設定ファイルだけの変更も含みます。

## 2. コードレビュー

### 2.1 プルリクエストの作り方
1件のプルリクエストの変更は400行以内を目安にします。説明欄には、対応するチケットの番号、変更の理由、動作を確かめた手順を書きます。

### 2.2 レビューの人数
マージには2名以上の承認が必要で、そのうち1名は対象のコードのコードオーナーとします。データベースの構造の変更と、ログイン・権限まわりの変更は、これに加えて開発部の管理職1名の承認を必要とします。

### 2.3 レビューの期限
レビューを頼まれた人は、依頼から2営業日以内に最初のコメントを返します。期限内に見られないときは、自分で別のレビュー担当者に交代を頼みます。

### 2.4 自動テスト
自動テストがすべて成功していないプルリクエストはマージできません。テストを一時的に止める場合も、開発部の管理職の承認が必要です。

## 3. 本番反映

### 3.1 反映できる曜日と時間
本番反映は、火曜日・水曜日・木曜日の10:00〜16:00に行います。月曜日、金曜日、祝日の前日、月末の最終営業日は反映しません。また、12月25日から1月7日までは反映を止める期間とします。

### 3.2 反映の申請
反映する日の前営業日の15:00までに、ワークフローシステムで「本番反映申請」を出し、開発部の管理職の承認を受けます。データベースの変更を伴う場合は、元に戻すためのスクリプトを申請に添付します。

### 3.3 緊急の反映
本番の障害を直すための変更に限り、開発部長の承認を受ければ、3.1の曜日と時間以外でも反映できます。この場合、翌営業日までに反映の内容と理由を報告します。

### 3.4 反映の体制
反映は、作業をする人と確認をする人の2名で行います。作業の手順は事前にチケットに書き、確認する人が1行ずつ確かめます。

## 4. 切り戻し

### 4.1 反映後の見張り
反映後60分間は、反映した2名がエラー率と応答時間を見張ります。この間は次の反映を行いません。

### 4.2 切り戻しの基準
エラー率が0.5%を超えた状態が5分続いたとき、または主な機能が使えないときは、作業した人の判断で直ちに切り戻します。上長の許可を待つ必要はありません。

### 4.3 切り戻しの手順
切り戻しは、直前に反映したリリースのタグに戻す方法で行います。15分以内に終えられるよう、手順を事前に検証環境で試しておきます。

### 4.4 切り戻した後の報告
切り戻した日のうちに開発部内のチャンネルで報告し、3営業日以内に原因と対策をチケットに記録します。社内システムに影響が出た場合は、情報システム部にも連絡します。
