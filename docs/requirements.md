# 要件定義

## 目的

社員が社内規程・マニュアルについてチャットで質問すると、該当する条文を引用して答える。書かれていないことには「規程に記載がありません」と答え、推測で答えない。部署・役職ごとに読める文書を分ける。

## 利用者

| 利用者 | したいこと |
| --- | --- |
| 一般社員 | 休暇・経費・申請の手順を、条文の根拠つきですぐ知りたい |
| 管理職 | 評価の運用など、管理職向けの手引きも含めて調べたい |
| 総務・人事・情シス（文書の管理者） | 規程を差し替えたら、その文書だけが索引に反映されてほしい |
| 情報セキュリティ担当 | 他部署・上位役職の文書が回答に混ざらないことを確かめたい |

## 機能要件と実装

| 番号 | 要件 | 実装 | 確かめ方 |
| --- | --- | --- | --- |
| F1 | Markdown・PDF・Word・HTML を取り込む | `loaders.py` | `tests/test_text_and_loaders.py` |
| F2 | 見出しの構造（章・条・節）を保って分割する | `loaders.py`・`chunker.py` | 同上 |
| F3 | 変更のあった文書だけを取り込み直す（追加・更新・削除） | `ingest.py`（中身と権限の情報のハッシュで比較） | `tests/test_ingest_and_search.py` |
| F4 | 日本語に強いハイブリッド検索 | `search.py`（ADR 002） | `scripts/evaluate.py retrieval` |
| F5 | 根拠の文書・該当箇所を引用して答える | `answer.py`・`prompt.py` | `scripts/evaluate.py answers` |
| F6 | 根拠がないときは「規程に記載がありません」 | 同上（ADR 004） | 同上（absent / restricted / attack） |
| F7 | 文書の中の命令に従わない | 同上（ADR 004） | 同上（injection / attack） |
| F8 | 部署・役職ごとに読める文書を検索の段階で分ける | `store.py`（ADR 005） | `tests/test_access_control.py`・`acl_audit` |
| F9 | 画面：質問・回答・根拠・文書の閲覧 | `web/` | `tests/e2e/`（Chromium・WebKit） |
| F10 | 公開デモは鍵なしで動く | `ReplayAnswerer`（ADR 006） | `tests/test_deploy.py` |

## 非機能要件

| 項目 | 内容 |
| --- | --- |
| 権限 | 読めない文書は検索結果・AIへの入力・文書の閲覧のどこにも出さない |
| 正確さ | 表示する引用は本文と一字一句一致するものだけ |
| 応答 | 検索は1問あたり十数〜二十数ミリ秒（32文書・439チャンク、このMac） |
| 画面 | 280×653 から 3840×2160 までの25種類の大きさで横はみ出し0、最初の画面に主な操作が収まる。WCAG 2.1 A/AA の自動検査で違反0 |
| セキュリティ | CSP（外部スクリプトなし）、入力の長さ制限、実運用モードの回数制限、トークンはハッシュだけを保存 |
| 運用 | 追加のサーバーなし（SQLite 1ファイル）。差分取り込みはコマンド1つ |

## 対応範囲

- 文書の形式：Markdown（フロントマター）、PDF（文字情報のあるもの。「第N章」「第N条」「1.」「1.1」の見出しを認識）、Word（見出しスタイル）、HTML（h1〜h6）。
- 画像だけの PDF（スキャン）は文字情報がないため、OCR を通してから取り込む。
- 認証：公開デモは閲覧者の選択、実運用はトークン。社内のシングルサインオンは `PrincipalResolver` を差し替えてつなぐ。
- 質問は1回ごとの独立した問答（会話の履歴を持たない）。
