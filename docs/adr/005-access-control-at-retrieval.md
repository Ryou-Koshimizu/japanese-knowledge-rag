# ADR 005：権限は検索の段階で絞る

- 状態：採用
- 日付：2026-10-20

## 背景

「検索した後に、読めない文書を捨てる」作りだと、捨てる前の結果がログ・AIへの入力・順位の計算に混ざる事故が起きやすく、上位がすべて読めない文書だったときに正解が押し出される問題もあります。

## 決定

- 文書ごとに「読める部署（`*` は全社）」と「読める最低の役職（一般社員／管理職／役員）」を持つ。Markdown はフロントマター、PDF・Word・HTML は同じ名前の `.meta.yaml` に書く。
- 4つの検索方式（語の一致・見出し・部分一致・埋め込み）の **すべての SQL に同じ権限の条件** を入れる。順位の計算も、AIへの入力も、権限で絞った後の集合だけで行う。
- 文書を開く API も同じ条件で引き、読めない文書は「存在しない」と同じ 404 を返す（存在そのものを知らせない）。
- 記録の再生（公開デモ）でも、記録した資料を権限の条件で引き直してから照合する。

## 保証のしかた

- 評価セットの全質問 × 6人の閲覧者で検索し、返った文書を **文書ファイル側の権限の定義から独立に** 照合する（`scripts/evaluate.py retrieval` の `acl_audit`、`tests/test_access_control.py`）。
- 読めない人が聞く質問（restricted）と質問の側からの乗っ取り（attack）で、AIに渡した入力の中に読めない文書の本文が1行も含まれないことを試験する。
- 方式ごとに単独でも検索し、どの方式も権限の外を返さないことを試験する。
